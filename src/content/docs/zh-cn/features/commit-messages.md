---
title: 提交信息
description: 一键根据已暂存的 diff 生成提交信息。
---

在源代码管理视图中，标题栏的闪光图标运行 **Twinny - Generate commit message**。twinny 读取 diff，向对话提供者请求一条信息，并写入提交框供你在提交前编辑。

## 使用哪个 diff

有已暂存的变更就用它们；否则用所有未暂存的。先暂存你打算提交的文件，信息就会准确描述这些内容。该命令需要内置 Git 扩展和已打开的仓库。

diff 上限为 24,000 字符，在文件边界截断，以免小型本地模型不堪重负；部分 diff 被省略时信息中会注明。非常大的提交请分批暂存和提交。

## 信息风格

默认提示（`commit-message.hbs`）要求：

- 祈使语气（“Add”、“Fix”、“Refactor”），
- 主题行少于 72 个字符，
- 只在主题无法说明时才加简短正文，
- 只输出信息本身，不带围栏、引号或解释。

由于小模型并不总是遵守，回复仍会被清理掉多余的围栏和引号。

## 定制

编辑 `~/.twinny/templates/commit-message.hbs` 改变风格。常见改法：

- **Conventional Commits**：要求 `type(scope): subject` 并列出允许的类型。
- **工单引用**：要求模型保留分支名中的工单号；若在对话中写信息，用 `@git` 附上分支。
- **语言**：要求用团队的语言写信息。

机制见[提示词模板](/twinny-docs/zh-cn/features/templates/)。

## 在对话中

也可以在对话中附上 `@git` 来写提交信息，想先讨论修改时很方便。日常情况下源代码管理按钮更快。
